# مسیرهای کاربر و ماشین حالت

> ماشین حالت زیر در `src/domain/mission-state.ts` پیاده‌سازی و تست شده است (منطق خالص؛ بدون داده‌ی فروشگاه).

## ۱. حالت‌های ماموریت خرید

```
UNDERSTAND_NEED → EXPLORE_PRODUCTS → SELECT_PRODUCT → DISCOVER_SELLERS
      → COMPARE_SELLERS → CONTACT_PREPARATION → CONTACT_RESULT → VISIT_PLAN
```

| حالت | هدف | خروجی پایدار در context |
|---|---|---|
| UNDERSTAND_NEED | فهم نیاز (کاربرد، بودجه، اولویت، قید سخت) | `intent`, `useCase`, `budget`, `priorities` |
| EXPLORE_PRODUCTS | کاندیداهای مبتنی بر کاتالوگ | `candidates[]` |
| SELECT_PRODUCT | انتخاب محصول و variant دقیق | `chosenVariant` |
| DISCOVER_SELLERS | یافتن offerهای منطبق نزدیک | `region`, `radius`, `sellerShortlist` |
| COMPARE_SELLERS | مقایسه‌ی قیمت/فاصله/ساعت/شرایط | `selectedSellers[]` |
| CONTACT_PREPARATION | پیش‌نویس پرسش‌ها (بدون ارسال) | `questions[]`, `drafts[]` |
| CONTACT_RESULT | ثبت دستی پاسخ فروشنده (خوداظهاری) | `responses[]`, `unresolved[]` |
| VISIT_PLAN | زمان و مسیر مراجعه | `visitTime`, `plan` |

### شاخه‌ها / حالت‌های خاص
| شاخه | از | به | رفتار |
|---|---|---|---|
| ابهام | هر حالت | سؤال شفاف‌ساز (همان حالت) | حداکثر ۱–۳ سؤال؛ قیود قبلی حفظ می‌شود |
| بدون نتیجه | EXPLORE / DISCOVER | UNDERSTAND_NEED یا بازتر کردن قید | پیشنهاد افزایش بودجه/شعاع؛ کدام قید بیشترین حذف را کرد |
| داده نامطمئن | COMPARE | همان حالت + نشانگر | قیمت پرت/قدیمی/بدون قیمت جدا از مقایسه‌ی معتبر |
| عدم‌تطابق مدل | COMPARE | SELECT_PRODUCT | «این پیشنهاد مدل دیگری است»؛ بازگشت برای تأیید variant |
| قیمت قدیمی | COMPARE | CONTACT_PREPARATION | پیشنهاد «پرسیدن قیمت روز» |
| رد مجوز مکان | DISCOVER | انتخاب دستی منطقه | بدون خطای سخت؛ چیپ‌های منطقه |
| خارج از پوشش | DISCOVER | همان | «داده‌ها بیشتر ناحیه‌ی فردوسی/شیخ‌هادی/بهارستان را پوشش می‌دهد» |
| بدون پاسخ | CONTACT_RESULT | COMPARE یا CONTACT_PREPARATION | گزینه‌ی بعدی یا پرسش دوباره |
| بدون کانال تأییدشده | CONTACT_PREPARATION | VISIT_PLAN | «راه ارتباطی تأییدشده در داده‌ها موجود نیست» + مراجعه‌ی حضوری |

### اجازه‌ی بازگشت (برگشت‌پذیری)
هر حالت می‌تواند به هر حالت **قبلی** برگردد؛ دو استثنا: پرش به جلو فقط اگر مقدار لازم context موجود باشد، و از VISIT_PLAN می‌توان به COMPARE یا CONTACT_PREPARATION برگشت. قیود کاربر هنگام بازگشت پاک نمی‌شوند.

## ۲. مسیر الف — محصول نامعلوم (مشاور)

1. کاربر در `/` یا `/discover` نیاز را می‌نویسد یا ورودی سریع (چیپ) را برمی‌دارد.
2. UNDERSTAND_NEED: ≤۳ سؤال (کاربرد، بودجه، یک اولویت یا قید سخت). سؤال‌ها بر اساس دسته انتخاب می‌شوند.
3. EXPLORE_PRODUCTS: کارت‌های کاندیدا با «چرا مناسب است / تعادل / ناشناخته‌ها».
4. SELECT_PRODUCT: انتخاب variant؛ مقایسه‌ی مشابه جدا از دقیقاً-همین.
5. ادامه با مسیر مشترک (بخش ۴).

*وضعیت فاز ۱:* کنترل‌های محلی ترجیحات + ناحیه‌ی نتایج با پیام صادقانه‌ی «اتصال به کاتالوگ در فاز ۲».

## ۳. مسیر ب — محصول معلوم (جست‌وجوی سریع)

1. `/search?q=` با جعبه‌ی جست‌وجوی صفحه‌ی اصلی.
2. تطبیق نام/مدل؛ اگر چند variant → انتخاب variant (واحد قیمت: عدد/متر/حلقه).
3. مستقیم به DISCOVER_SELLERS.

*وضعیت فاز ۱:* ورودی و ناوبری کار می‌کند؛ نتیجه نشان داده نمی‌شود.

## ۴. مسیر مشترک پس از انتخاب محصول

- **DISCOVER_SELLERS**: منطقه (چیپ) یا موقعیت (در آینده)، شعاع، تنها offerهای دقیقاً منطبق + بخش جدا «مشابه».
- **COMPARE_SELLERS**: جدول/کارت قابل مرتب‌سازی؛ ستون‌ها: قیمت (با سن)، فاصله، ساعت اعلام‌شده، گارانتی، پرداخت (اعلام‌شده/اعلام نشده). هر ردیف «چرا این رتبه» دارد.
- **CONTACT_PREPARATION**: انتخاب نیت پرسش → پیش‌نویس فارسی → کپی/اشتراک توسط کاربر.
- **CONTACT_RESULT**: ثبت دستی پاسخ، خلاصه، پرسش‌های بی‌پاسخ، به‌روزرسانی وضعیت ماموریت.
- **VISIT_PLAN**: انتخاب زمان در ساعت کاریِ اعلام‌شده، ترتیب مراجعه، یادآور «پیش از رفتن تأیید کنید».

## ۶. موارد مرزی که باید پوشش داده شوند
- محصول با چند واحد قیمت (متر/حلقه) → سؤال واحد پیش از مقایسه.
- یک مغازه چند offer برای یک product_id (variant متفاوت) → نمایش گروه‌بندی‌شده، نه تکرار.
- مغازه بدون برنامه‌ی کاری → «ساعت اعلام نشده».
- مغازه‌ای که دسته‌اش مرتبط است ولی offer ندارد → هرگز کاندید نیست (دسته ≠ داشتن کالا).
