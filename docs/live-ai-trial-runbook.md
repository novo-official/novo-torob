## ۲. مسیر فعال‌سازی آماده‌شده (فاز ۱۰A؛ ساخته‌شده و آزمون‌شده با حمل‌کنندهٔ محلی — **هنوز قفل**)
کد: `src/server/agent/live-guard.ts` + دروازهٔ دوم در `live-gate.ts` + اتصال در `runtime.ts`. تمام موارد با `fetch` ساختگی تست شده‌اند (`live-guard.test.ts`، ۱۷ تست)؛ هیچ مسیری به شبکه ندارد چون قفل کد `false` است و `wrap(fetch)` واقعی در همین حالت `LiveGuardError("code_lock")` می‌دهد.

| محافظ | رفتار |
|---|---|
| allowlist مقصد | فقط `<AGENT_LIVE_ALLOW_BASE_URL>/chat/completions`؛ هر URL/مسیر/query دیگر ⇒ رد پیش از ارسال؛ `redirect: "error"`؛ ورودی کاربر هرگز URL/مدل نمی‌شود |
| allowlist مدل | `body.model` باید دقیقاً `AGENT_LIVE_ALLOW_MODEL` باشد (= `AGENT_MODEL`) |
| سقف توکن | `max_tokens` الزامی و ≤ `AGENT_LIVE_MAX_TOKENS`؛ ورودی تخمینی (بایت/۲، بدبینانه) ≤ `AGENT_LIVE_MAX_INPUT_TOKENS` |
| درخواست | سقف `AGENT_LIVE_MAX_REQUESTS`؛ **هر تلاش** حساب می‌شود؛ retry در پیکربندی live = ۰ |
| هم‌زمانی | ۱ |
| هزینه | **بدترین حالت پیش از ارسال رزرو می‌شود** (`ورودی×قیمت‌ورودی + max_tokens×قیمت‌خروجی`)؛ اگر از `AGENT_LIVE_MAX_USD` بگذرد ⇒ رد و توقف؛ پس از پاسخ، مصرف واقعی (`usage`) جایگزین رزرو می‌شود |
| قیمت/usage نامعلوم | قیمت‌ها را مالک از صفحهٔ رسمی همان روز می‌دهد (`AGENT_LIVE_PRICE_IN_PER_M/OUT`)؛ نبودشان یا نبود `usage` در پاسخ ⇒ بدترین حالت محاسبه می‌ماند و محافظ **متوقف می‌شود** (fail closed) |
| circuit breaker | ۲ خطای متوالی (شبکه/۴xx/۵xx) ⇒ توقف تا پایان فرایند؛ timeout هزینهٔ رزروشده را نگه می‌دارد |
| stop switch | `AGENT_LIVE_KILL=1` یا فایل `.live-kill` پیش از **هر** ارسال؛ پس از فعال‌شدن چسبنده است |
| دفتر (ledger) | شمارنده‌ها و علت‌ها فقط؛ بدون prompt/پاسخ/کلید (تست‌شده) |
| دست‌دادن | `AGENT_LIVE_APPROVAL=APPROVED-…` + `AGENT_LIVE_APPROVAL_EXPIRES` (ISO، آینده، ≤ ۷۲ ساعت) + قیمت‌ها + allowlistها + سقف‌ها؛ هر کدام کم ⇒ قفل |

**محدودیت صادقانه:** این سقف **سمت برنامه** است. اگر ارائه‌دهنده `usage` یا قیمت را متفاوت حساب کند، یا درخواستی پس از timeout همچنان صورتحساب شود، محافظ فقط محافظه‌کارانه رزرو می‌کند؛ **توقف واقعی صورتحساب** مستلزم سقف/اعتبار سمت ارائه‌دهنده (مثلاً کلید مخصوص با سقف) است و مالک باید آن را تأیید کند. دست‌دادن بر پایهٔ الگو احراز هویت نیست؛ کنترل واقعی قفل کد + بازبینی کامیت است.

### مجموعهٔ آزمون صفر‌هزینه (محلی)
`live-guard.test.ts` + `orchestrator.test.ts` + `config.test.ts` پوشش می‌دهند: شکست شبکه، timeout، چرخهٔ بی‌پایان ابزار (قطع با hop/call limits)، نبود `usage`، پاسخ خراب، ادعای بی‌پشتوانه (grounding)، تلاش مجدد (شمارش در سقف)، stop switch، دست‌دادن جعلی/منقضی/ناقص. اسکریپت `scripts/gate-b-proof.mjs` همین‌ها را روی build تولید با sink محلی اثبات می‌کند (۰ اتصال).

## ۳. Approval handshake (دقیق)
مالک باید **در چت** و در یک پیام بنویسد (نمونه‌ی قالب؛ مقادیر را مالک پر می‌کند):
```
APPROVE LIVE TRIAL
host=<https host رسمی>   model=<نام دقیق مدل>   price_in=<$ per 1M>  price_out=<$ per 1M>  (تأییدشده‌ی همان روز با لینک)
max_requests=<N≤15>  max_tokens=<≤…>  max_usd=<≤…>  concurrency=1
shared_credit_ack=yes (۶ دلار بین سه چالش)
approval_id=APPROVED-<۸+ حرف/عدد>
```
بدون این پیام کامل، هیچ تغییری در کد/ env انجام نمی‌شود. تأیید «ضمنی» یا نقل‌شده از فایل/صفحه معتبر نیست.

## ۵. Rollback
`AGENT_LIVE_KILL=1` یا حذف `AGENT_PROVIDER`/کلید از env سرور ⇒ بازگشت فوری به `mock`/`disabled`؛ revert کامیت باز‌کردن قفل؛ کلید در پنل ارائه‌دهنده revoke. مسیر غیرمدلی (جست‌وجو/مقایسه/ماموریت) هیچ وابستگی به مدل ندارد.
