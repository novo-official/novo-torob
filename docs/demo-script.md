## صحنه‌های مرزی (تمرین‌شده در `demo-rehearsal.spec`)
* **variant مبهم (≈ ۱:۳۰):** صفحهٔ یک محصول با پرچم `VARIANT_MODEL_MISMATCH` (یافتن با پرس‌وجوی DB در تست) ← هشدار «لزوماً یک کالای یکسان نیستند» ← انتخاب صریح نسخه ← `?variant=` در URL. گفتار: «سیستم هویت کالا را خودش تأیید نمی‌کند.»
* **بدون نتیجه + محلهٔ تخصصی (≈ ۴:۲۵):** `/assistant` ← «دوربین مداربسته مدل ZZ9999X رو می‌خوام نزدیک بهارستان» ← پاسخ «نمونه‌ی محدود»، کارت‌های منطقه با «فروشنده نیست» و «اطمینان»، بدون هیچ فروشندهٔ ساختگی. بنر بالای صفحه: «هیچ مدل زبانی‌ای در کار نیست».
* ادامهٔ فهرست قدیمی:
بدون نتیجه (جست‌وجوی بی‌معنی) · GPS رد شده ← انتخاب محله · فروشگاه بدون کانال عمومی ← «راه ارتباطی تأییدشده موجود نیست» + مراجعه حضوری · خطای مدل دیگر (variant mismatch) در DEMO ← «تأیید مدل لازم است».

## راهبرد ضبط پشتیبان (fallback)
1. **ضبط دوبار:** یک بار «زنده» روی `npm start`، یک بار از Docker؛ هر دو با داده‌ی همین DB (sha256 باید با `scratchpad/db.sha` برابر باشد).
2. هر صحنه جدا ضبط شود؛ اگر صحنه‌ای خراب شد فقط همان تکرار می‌شود (بدون وابستگی به شبکه خارجی؛ نقشه‌ی OSM ممکن است کند باشد ← در همان صحنه به لیست برگردید و بگویید «نقشه اختیاری است»).
3. اگر شبکه نیست: نقشه خالی است ولی لیست/مقایسه کامل کار می‌کند (تست‌شده).
4. هرگز خروجی صفحه‌ی `AGENT_PROVIDER=live` ضبط نشود (قفل است و ۵۰۳ می‌دهد).
5. اسکرین‌شات‌های مرجع: `docs/qa/*.png` (۳۶۰/۳۹۰/۷۶۸/۱۰۲۴/۱۴۴۰).
