# بازطراحی جست‌وجو و کارت محصول — بستهٔ دوم

تاریخ: 2026-10-22 — ۱۴۰۵/۰۷/۳۰

دامنه: بخش جست‌وجو و کارت مشترک از فاز ۳ برنامه. بازطراحی اختصاصی گردش مشاور و صفحهٔ جزئیات محصول هنوز باقی است؛ کارت تازه در نتایج مشاور نیز استفاده می‌شود.

## خروجی

- فرم جست‌وجوی خوانا با label نمایان، پاک‌کردن عبارت، وضعیت پردازش و پیشنهادهای قابل استفاده با لمس و صفحه‌کلید.
- لغو درخواست پیشنهاد قبلی؛ نمایش پاسخ فقط برای همان عبارت و جلوگیری از برگشت پیشنهاد دیررس پس از پاک‌کردن ورودی.
- Escape انتخاب فعال را پاک می‌کند؛ Enter پس از بستن پیشنهادها، عبارت فعلی را جست‌وجو می‌کند.
- پیشنهادها تا سقف ۸۰ نویسهٔ API دریافت می‌شوند؛ عبارت بلندتر تا سقف ۱۲۰ نویسه همچنان با جست‌وجوی کامل قابل استفاده است.
- فرم GET بدون JavaScript از حالت خالی هم قابل استفاده است و دسته را حفظ می‌کند.
- فیلترهای دسته با تعداد واقعی، دستهٔ فعالِ قابل حذف، شمارش محدودهٔ همین صفحه و صفحه‌بندی با حفظ query/category.
- حالت‌های شروع، عبارت نامعتبر، بدون نتیجه، تطبیق جزئی و صفحهٔ خالیِ پس از پایان نتایج، متن و اقدام متناسب دارند.
- مدل/برند تکراری در عنوان دوباره نمایش داده نمی‌شود؛ هویت داده در عنوان اصلی حفظ شده است.
- قیمت ثبت‌شده، واحد قیمت، قدیمی‌بودن و موجودی تأییدنشده روشن‌اند؛ هشدار نسخه و واحد در نمای اصلی باقی مانده و جزئیات شمارش بازشدنی است.
- قیمت غیرقابل اتکا به بازهٔ عددیِ قابل خرید تبدیل نمی‌شود؛ منطق قیمت، رتبه‌بندی و داده‌های سرور تغییر نکرده‌اند.
- انتخاب مقایسه بازخورد واضح و نام دسترس‌پذیر سازگار با متن دارد؛ در سقف چهار محصول، دلیل غیرفعال‌بودن انتخاب تازه نمایان است.
- تصویر ناموجود/خراب جایگزین دارد؛ تغییر URL تصویر پس از خطا، اجازهٔ نمایش تصویر جدید را می‌دهد.
- بازگشت از کارت نتیجه یا پیشنهاد جست‌وجو، زمینهٔ عبارت را حفظ می‌کند؛ انتخاب پیشنهاد هم لینک بازگشت به نتایج دارد.
- متن حالت دادهٔ در دسترس نبودن و خطای مشترک، کاربرپسند شده و دستور فنی از گردش کار حذف شده است.

این مقادیر هندسهٔ همین دادهٔ آزمایشی‌اند؛ سرعت انجام کار توسط انسان یا performance میدانی را ثابت نمی‌کنند. منابع: [قبل](before/measurements.json) و [بعد](after/measurements.json). در هر ۴۰ ترکیب اندازه/حالت/تم پس از تغییر، عرض سند از viewport بیشتر نبود.

## اجرای دوباره

```bash
npm run qa:search
```

این دستور build با Webpack می‌سازد، fixture جدا آماده می‌کند، سرور تست روی پورت ۳۱۱۴ بالا می‌آورد، ۱۱ سناریو را اجرا می‌کند و سرور تست را می‌بندد. پورت با `SEARCH_QA_PORT` قابل تغییر است. به `data/app.sqlite` نمی‌نویسد و به دادهٔ واقعی یا مدل زبانی وابسته نیست.

## تصمیم بارگذاری و بازیابی خطا

در نسخهٔ Next 16.4.2، مرز `search/loading.tsx` می‌توانست نتیجهٔ server-rendered را در حالت بدون JavaScript پشت محتوای hidden مربوط به streaming نگه دارد. این مرز از مسیر جست‌وجو برداشته شد؛ نتیجهٔ اولیه با HTML سرور می‌آید. جست‌وجوی بعدی از طریق `useTransition`، وضعیت پردازش و دکمهٔ pending دارد و در تست شبکهٔ کند بررسی شده است. skeleton مشترکِ سایر مسیرهای کاتالوگ حفظ و از نظر ابعاد خواناتر شده است.

بازیابی خطای همین مسیر با `retry()` نسخهٔ نصب‌شده انجام می‌شود تا دادهٔ segment دوباره دریافت شود. راهنمای error، router، CSS و navigation از مستندات محلی همان Next خوانده شد.

## محدودیت‌ها و ادامه

- دیتاست واقعی در workspace موجود نیست؛ skippedها موفق حساب نشده‌اند.
- تست‌ها روی Chrome و شبیه‌سازی اندازه/لمس انجام شده‌اند؛ گوشی واقعی، کیبورد مجازی واقعی، صفحه‌خوان و Safari/Firefox تأیید نشده‌اند.
- کیفیت تصاویر واقعی محصول و عملکرد جست‌وجو روی کاتالوگ کامل با این fixture اثبات نمی‌شود.
- هیچ کتابخانهٔ تازه‌ای اضافه نشده؛ تغییر `package.json` فقط اسکریپت `qa:search` است.
- ادامهٔ فاز ۳: بازطراحی اختصاصی گردش مشاور و جزئیات محصول/انتخاب نسخه، بر اساس همین کارت و اجزای پایه.
